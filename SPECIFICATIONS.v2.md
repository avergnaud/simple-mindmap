# DAG KB — MVP Specifications

## Overview

A personal knowledge management tool built around a mindmap structured as a DAG (Directed Acyclic Graph) / Knowledge Graph.

Two separate interfaces:

- **Claude skill** (run via Claude Code): intelligent operations — extract content into subgraphs, insert/merge subgraphs into the DAG, edit nodes interactively.
- **Webapp** (localhost): manual CRUD only — view the mindmap, add a child node, delete a node, copy a node ID.

There is **no call to the Claude API** at runtime. The webapp does not call Claude. All intelligence comes from the Claude skill executed via Claude Code.

### Node matching

There is a recurring need to match nodes (e.g. when merging a new subgraph into the existing DAG, we must detect if some nodes already exist). Matching on title alone is unreliable (e.g. "NIST RMF" vs "NIST Risk Management Framework"). Each node therefore carries a list of **5 synonyms** generated by the Claude skill. The skill uses context from the **input material folder** (configured in `config.json`) to generate relevant synonyms. The user may edit synonyms via the Claude skill.

## Configuration

Project configuration is stored in `config.json` at the project root.

| Field                | Type   | Required | Description                                              |
|----------------------|--------|----------|----------------------------------------------------------|
| `input_material_dir` | string | yes      | Path to the folder containing source material (absolute or relative to project root) |

Example:

```json
{
  "input_material_dir": "../CISSP-notes"
}
```

## Data Model

All data is stored on disk as two JSON files in the `data/` folder.

### nodes.json

An array of node objects.

| Field         | Type     | Required | Description                                |
|---------------|----------|----------|--------------------------------------------|
| `id`          | string   | yes      | Unique identifier (e.g. UUID)              |
| `title`       | string   | yes      | Short label displayed in the UI            |
| `synonyms`    | string[] | yes      | 5 title synonyms, generated by the skill  |
| `description` | string   | no       | Longer text, shown on expand               |

### edges.json

An array of edge objects.

| Field         | Type    | Required | Description                                         |
|---------------|---------|----------|-----------------------------------------------------|
| `source`      | string  | yes      | Node id of the parent                               |
| `target`      | string  | yes      | Node id of the child                                |
| `type`        | string  | yes      | Relationship type (e.g. "contains", "implies", "relates to") |
| `description` | string  | no       | Optional description of the relationship            |
| `primary`     | boolean | yes      | If `true`, this edge defines the primary parent link used for display hierarchy |

### Constraints

- The graph is a DAG — no cycles allowed.
- A node may have zero or more parents (zero parents = root node).
- A node must have **exactly one** primary parent edge, except root nodes which have none.
- There must be exactly one root node.

## Claude Skill

The skill is executed via Claude Code. It reads/writes `data/nodes.json` and `data/edges.json` directly.

### Capabilities

#### 1. Extract a subgraph from input material

- The user provides text (pasted, or a file path from the input material folder configured in `config.json`).
- The skill extracts key concepts as nodes (title + 5 synonyms + optional short description).
- The skill organizes them hierarchically where the content implies hierarchy.
- The skill produces a subgraph written as two JSON files: `data/subgraph_<timestamp>_nodes.json` (array of nodes) and `data/subgraph_<timestamp>_edges.json` (array of edges).
- Edge type defaults to `"contains"` for hierarchical relationships, `"relates to"` or `"implies"` when the content suggests those.

#### 2. Insert/merge a subgraph into the DAG

- The skill compares the subgraph's nodes against existing nodes using synonym matching.
- Existing nodes are reused (merged); new nodes are created.
- The user specifies (or the skill suggests) the attachment point in the existing DAG.
- The subgraph root(s) get a primary edge from the attachment node.

#### 3. Edit a node

- The user provides a node ID (copied from the webapp).
- The skill allows interactive editing of title, description, and synonyms.

## Webapp — Localhost

A single-page web application served on localhost (e.g. `http://localhost:3000`). Manual CRUD only.

### Display

- Nodes are displayed as an **indented list**, top to bottom, left to right.
- Indentation is determined by the **primary parent** hierarchy only.
- The root node appears at the top level.
- Children are indented below their primary parent.
- **Secondary parents** (non-primary edges pointing to a node) are not shown as indentation links. Instead, a subtle visual hint on the node (e.g. a small icon or badge) indicates that other parent relationships exist. Clicking it reveals the list of secondary parents.
- The UI must be as simple as possible — no fancy graph layout, no dragging, no canvas. Just an indented list.

### Features

#### 1. Add a child node (manual)

- Each node has a "+" button.
- Clicking it opens a small form: title (required), description (optional).
- On submit, a new node is created (with an empty synonyms list) and a primary edge is added from the parent node to the new node.
- The edge type defaults to `"contains"`.

#### 2. Copy node ID

- Each node has a "copy ID" button.
- Clicking it copies the node's UUID to the clipboard.
- Used to reference the node when working with the Claude skill.

#### 3. Delete a node (cascade)

- Each node has a delete button.
- Deleting a node **deletes the entire subtree** below it (all descendants via primary parent edges).
- All edges involving deleted nodes are also removed.
- A confirmation prompt is shown before deletion.

### Tech Stack (suggested)

- **Backend:** Node.js with Express (or similar lightweight server). Serves the webapp and provides a REST API to read/write the JSON files.
- **Frontend:** Vanilla JS, or a lightweight framework (e.g. Alpine.js). Keep it minimal.

---

## Out of Scope (for MVP)

- Drag-and-drop reparenting
- Search / filter
- Multi-root support
- Undo / redo
- Export
- Node editing from the webapp (done via Claude skill)
- Any Claude API call at runtime
